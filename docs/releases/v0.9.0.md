# v0.9.0 — Media + Create

## Summary

ProofMode now has the MVP post-media path: a signed-in member can choose or capture proof media, upload it directly to Cloudflare without receiving server credentials, recover an interrupted upload, and create a post that advances through server-owned processing and moderation state before publication.

## Changes

- Replaced the Post shell with a six-mode proof composer for Proof, Fail, Almost, Comeback, PR, and Reset.
- Added joined-public-Drop selection, captioning, camera/library media selection, and client-side size/duration checks.
- Added persistent local pending-media copies and native upload progress/retry/discard using Expo FileSystem.
- Added short-lived direct R2 PUT intents for images and direct Cloudflare Stream upload URLs for videos.
- Added bearer-session validation, Drop-membership authorization, and lightweight per-user intent throttling on the Next backend.
- Added R2 upload verification before an image becomes ready.
- Added signed Stream webhook handling with freshness and constant-time HMAC verification.
- Added database-owned media/post lifecycle transitions and durable moderation enqueueing through the existing `job_outbox`.
- Added daily abandoned-upload cleanup protected by `CRON_SECRET`.
- Home now renders published images and HLS videos; off-screen feed videos pause automatically.
- Added migration `008_media_post_lifecycle.sql` and transactional pgTAP lifecycle coverage.

## Limits

- Images: 20 MB maximum; JPEG, PNG, or WebP.
- Videos: 200 MB maximum and 120 seconds maximum; MP4 or QuickTime.
- v0.9 posting is public and requires membership in a public Drop.

## Security

Mobile receives only a Supabase user session plus short-lived provider upload URLs. `SUPABASE_SERVICE_ROLE_KEY`, R2 credentials, Stream API tokens, webhook secrets, and `CRON_SECRET` stay server-side. Media/post publication state is not client-controlled.

## External release gates

The code does not fabricate provider readiness. Before device-level release validation, the deployment still needs real Cloudflare R2/Stream credentials, a Stream webhook secret/registration, the public R2 delivery base URL, `CRON_SECRET`, and physical-device camera/library tests. A moderation worker/provider must process the queued moderation jobs before ordinary posts can automatically reach `published`.
