# v0.7.0 — Email magic-link authentication

## Summary

ProofMode now uses the plan-required passwordless email fallback on mobile. The temporary email/password bootstrap path has been removed.

## Changes

- Replaced password sign-in/sign-up with `signInWithOtp` magic links.
- Added a single `proofmode://auth` mobile auth callback.
- Added cold-start and foreground deep-link handling to the existing root session provider.
- Completes the Supabase session from returned access/refresh tokens.
- Surfaces deep-link authentication errors on the auth screen.
- Added local Supabase redirect configuration for `proofmode://auth`.
- Kept public Home/Explore and existing auth-gated actions unchanged.

## Remaining provider setup

The hosted Supabase project must allow `proofmode://auth` as an Auth redirect URL before physical-device magic-link testing. Apple and Google remain the next auth slice because they require provider-side credentials/configuration.
