# v0.6.0 — Staging gate and CI hardening

## Summary

ProofMode's first live Supabase staging gate is complete through migration `006_staging_hardening`.

## Changes

- Applied migrations `001` through `006` to the isolated Proofmode staging project.
- Corrected the launch library from 65 rows to the canonical 60 templates.
- Moved RLS-only `SECURITY DEFINER` helpers into a non-exposed `private` schema.
- Removed the obsolete `join_public_challenge` RPC and its web fallback.
- Restricted the billing synchronization RPC to `service_role`.
- Explicitly restricted client RPC grants and future public-function defaults.
- Added pgTAP regression coverage for the security boundary.
- Fixed CI to use `supabase start` and added database linting.
- Added CI concurrency cancellation, read-only workflow permissions, and job timeouts.

## Verification

Live staging checks confirmed:

- exactly 60 launch templates;
- private helper functions are no longer public RPCs;
- anonymous feed access remains available;
- challenge join remains authenticated-only;
- billing synchronization remains service-role-only.

Supabase security advisors now report only intentional public `SECURITY DEFINER` API endpoints and informational server-only RLS tables.
