# v0.9.0 Audit Note — Feed Publication Time

The full-system pre-release audit found that `get_feed_v1` accepted rows whose `published_at` timestamp was in the future. Current staging data contained no affected rows, but the RPC contract allowed them.

Migration `009_feed_publication_time_guard.sql` keeps the existing deterministic feed score and keyset ordering unchanged while requiring `published_at <= now()` before a post is eligible for the public feed.

Transactional pgTAP coverage now proves that a future-dated published and approved public post is excluded and that the existing pagination cursor still reaches the expected next row.
